# 需求与验收条件

[English](requirements.md) · 简体中文

## 已确认需求

- 首个验证场景两端均使用 Ubuntu、Niri 和 Wayland，保留当前桌面环境。
- 首个多屏场景为台式机两块显示器，一块竖屏、一块横屏，笔记本位于横屏下方。这是验收场景，不是硬件限制。
- 笔记本触摸板移动指针进入台式机后，笔记本内置键盘和触摸板共同控制台式机。
- 台式机鼠标移动指针进入笔记本后，连接台式机的 2.4G 分体式键盘和鼠标共同控制笔记本。
- 键盘跟随指针控制目标，无须单独切换键盘或移动接收器。
- 返回输入来源电脑时恢复本机操作。
- 两端都必须支持 Niri 快捷键及应用内键盘输入。
- 在现有 KDE Connect 自动共享剪贴板的环境中正常工作。本项目不实现第二套剪贴板同步，也不以 KDE Connect 为键鼠共享的必要依赖。
- 接收方实体键鼠有操作时自动结束共享，两台电脑各自恢复本地控制。注入的远端事件不触发接管。
- 任一端锁屏即暂停共享，释放捕获与模拟按键；解锁后允许重新进入共享，不自动恢复先前的输入独占。
- 三指工作区切换、四指窗口总览等触摸板手势同样跟随指针，在当前控制的电脑执行；返回后恢复本机手势。
- 提供原生桌面前端，屏幕连接在一台调整后自动同步两端。
- 面向英语母语社区用户，以英文为源语言，提供完整简体中文翻译、系统语言跟随和手动切换。

## 可供社区使用的要求

- 主机名、地址、输出名称、分辨率、缩放及输入设备均不能写死为个人环境。
- 示例使用通用名称和虚构地址，个人机器记录保存在 Git 忽略的 `.local/` 目录。
- 从实际接口和设备能力判断可用后端，不仅按版本号推测支持。
- 首版聚焦两台 Niri 设备，不据此承诺其他合成器、发行版或多机拓扑已经受支持。
- 添加代码时提供实际可运行的构建与验证命令；许可与代码来源可追溯。

## 建议的首版边界交互

以下为设计提案，具体入口范围需要校准：

- 右侧横屏底边的一段与笔记本顶边相连。
- 横屏入口向下进入笔记本；笔记本顶边向上返回横屏。
- 位置按逻辑坐标和归一化边界位置映射，处理缩放与旋转。
- 提供紧急返回组合键，具体键位需检查现有绑定后确定。

## 实施相关行为前需确定的问题

- 两端恰好同时发起新的跨设备控制请求时的仲裁规则。
- 精确的屏幕入口范围，以及将来是否需要其他边界。
- 实际纳入共享的物理设备及紧急返回组合键。

这些问题不阻止只读探查、后端能力验证及纯逻辑开发；不能在实现中静默确定影响用户工作流的规则。

## 验收清单

基本双向操作由实际用户确认；其余条目保留各自的验证边界，不以自动测试代替实机验收。

- [x] 笔记本触摸板与内置键盘能控制台式机，并正常返回。
- [x] 台式机的鼠标与分体式键盘能控制笔记本，并正常返回。
- [x] 指针跨设备时，键盘同步切换；隔离集成测试同时检查来源窗口未收到发往对端的按键。
- [x] 三指切换和四指总览随控制目标切换。目标 uinput 手势探测通过，用户反馈其他操作正常。
- [ ] 台式机两块显示器之间的本地移动正常。
- [ ] 两端 Niri 快捷键、中文输入、修饰键和应用快捷键正常。
- [ ] 鼠标按钮、侧键、滚轮及触摸板点击、双指滚动正常。
- [ ] 按键或鼠标按钮按住时跨边界，状态保持一致且不会卡键。
- [ ] 断网或进程退出后，发送端恢复本地控制，接收端超时释放模拟按键。
- [ ] 紧急返回机制不依赖网络回复。
- [ ] 休眠恢复、设备热插拔和输出布局变化后可恢复。
- [ ] 注入的虚拟输入不会再次被当作物理输入向网络转发。
- [x] 未认证对端无法控制输入；网络事件经过认证与加密。已测试错误服务端名称、未信任服务端和未配对客户端的拒绝路径。
- [ ] KDE Connect 剪贴板同步保持正常，跨设备复制粘贴通过双向验证。
- [ ] 记录实际输入延迟与抖动，以及高频鼠标输入下的表现。

- [x] 两台实机托盘注册、菜单、打开、暂停、启动与退出；配置和自动启动状态保留。
