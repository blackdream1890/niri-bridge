# 设计与验证依据

[English](design.md) · 简体中文

## 当前实现

NiriBridge 在两台 Ubuntu/Niri 设备间双向共享键盘、鼠标和触摸板。用户已验证基本双向控制，以及三指工作区切换和四指窗口总览跟随目标电脑。两端使用同一 release 程序，以普通用户服务运行。

控制方向与 TCP 连接方向无关：一端监听、另一端连接，两端均可作为实体输入来源。键盘、触摸板手势随指针切换；接收方实体输入结束共享。任一会话锁定、不活跃或状态未知时暂停，解锁后需要重新进入边界。

## 输入路径

| 输入 | 来源端 | 目标端 |
| --- | --- | --- |
| 键盘 | 读取选定实体键盘的 evdev 事件；Wayland 捕获区域负责焦点和本机快捷键抑制 | uinput 虚拟键盘进入 Niri 和目标输入法 |
| 鼠标 | layer-shell 边界、相对指针、指针锁定和快捷键抑制 | wlr-virtual-pointer，落点按输出逻辑坐标和变换映射 |
| 原生触摸板 | 读取选定触摸板的多点触控帧，按控制目标选择本机或远端 | uinput 虚拟触摸板，由目标 Niri/libinput 原生识别移动、点击、滚动和手势 |

源端在指针锁定、键盘焦点和快捷键抑制均就绪后才开始远程控制。边界使用输出名称与归一化入口范围，不写死主机、分辨率或缩放。已有按住的键在进入共享时同步；同一个键在多个实体键盘上同时按下时按合并状态转发，忽略内核重复值，由接收端处理正常按键重复。

启用 `native_touchpads` 时，连接可用且会话未锁定期间，程序接管选定触摸板，通过本地虚拟触摸板保持本机操作，通过远端虚拟触摸板执行共享操作。初次接管等待所有手指离开，保证原来的 Niri 设备处于无接触状态。跨屏时同步当前触点，结束时释放虚拟触点和按钮；锁屏、断线或进程退出时关闭设备句柄并释放独占。键盘只读，不独占。

触摸板仅支持已校验的 slot-based 多点触控设备，限制设备数、轴范围、触点数和帧大小。能力描述不含原设备名称、序列号或路径。来自 NiriBridge 的虚拟设备不能纳入实体输入监测，避免事件回流。

## 为什么采用这些后端

两端实际宣告了所需 Wayland 接口，但接口存在不能证明所有行为可用。两端 portal 宣告 InputCapture/RemoteDesktop，对应 Mutter 服务没有运行；项目没有依赖未经验证的 portal 会话。

[Smithay 的虚拟键盘实现](https://github.com/Smithay/smithay/blob/ff5fa7df392cecfba049ffed55cdaa4e98a8e7ef/src/wayland/virtual_keyboard/virtual_keyboard_handle.rs) 直接向聚焦客户端发送按键。隔离实测证明它不能触发所测试的 Niri 全局绑定，因此接收端使用 uinput 键盘。

实际 Fcitx5 会话复现了 Wayland 焦点交接时丢键：收到客户端焦点和快捷键抑制事件后，旧输入法抓取仍可能没有释放。[Smithay 输入法代码](https://github.com/Smithay/smithay/blob/ff5fa7df392cecfba049ffed55cdaa4e98a8e7ef/src/wayland/input_method/input_method_handle.rs) 通过异步协议通知停用。源端以实体键盘事件为唯一按键来源，解决输入法过滤问题；程序不修改或停用输入法。

Niri 的三指和四指手势在合成器中直接处理，指针锁定不能阻止来源电脑执行这些桌面动作。因此原生触摸板帧必须在 Niri 之前选择目的地，由目标电脑的虚拟触摸板恢复原生手势，而不是把触点坐标误当作鼠标位移。

## 时序与恢复

- 触摸板文件描述符使用异步可读通知，事件到达即处理，避免固定轮询额外增加等待。
- 原始帧使用 `CLOCK_MONOTONIC`。本机镜像保留硬件时间戳；跨机按相对时序映射到接收机时钟，保留原始帧间隔，防止批量重放扭曲 libinput 的加速计算。
- 网络帧与虚拟输入使用有限大小和有效数值。输入队列过旧、写入阻塞、连接超时或事件丢失时释放控制。
- 虚拟设备创建后检查当前 Niri 已打开该设备，再执行 IPC 往返；不以固定启动延时代替就绪检查。
- 绝对指针落点先做输出变换的逆映射。Wayland 滚动来源放在同一 frame 的轴数据之后，保留 Niri 的 Finger 来源信息。
- 断线、接管、锁屏、输出重配置和退出均清理按键、按钮、触点与捕获。紧急返回组合键是 Ctrl+Alt+Shift+Escape，普通 Escape 正常转发。

## 认证与数据边界

连接采用双方证书认证的 TLS 1.3，仅信任显式交换的对端证书。协议版本和 ALPN 必须一致；设备能力先于输入协商，之后检查会话号和递增序号。两个来源同时请求控制时拒绝重入并恢复本机操作。

程序不记录按键、触点坐标、剪贴板或密钥，不传输桌面视频。不实现剪贴板同步，已有 KDE Connect 继续负责这部分。设备权限由最小范围的管理员安装器配置，运行程序不使用 root。

## 依赖修正与验证

实际设备上确认 evdev 0.13.2 的 UI_SET_PHYS 编码错误会返回 EINVAL，固定到上游修复提交 [7fee138a](https://github.com/emberian/evdev/commit/7fee138a341f73b81b9c4f8c59e3527c6a169ea3)。没有修改共享 Cargo 缓存或将依赖源码复制进项目。

常规检查、隔离 Niri 集成测试和显式的实际输入探测见 [测试说明](testing.zh-CN.md)。它们分别验证纯逻辑、真实隔离合成器和实际输入后端。用户已确认双向键鼠及三指、四指手势；长期休眠恢复、高频鼠标、完整中文编辑场景和全部扩展输入仍需持续验收。

参考：[Linux 输入事件语义](https://docs.kernel.org/input/event-codes.html)、[Linux uinput](https://docs.kernel.org/input/uinput.html)、[Niri 安全模型](https://niri-wm.github.io/niri/Security-Model.html)。

## 桌面管理

Rust 用户服务负责输入与恢复，Python/GTK 界面负责交互。界面通过权限为 0600 的私有 Unix socket 通信，检查同一用户身份，实例锁防止重复占用。状态来自实际后端，包括连接、控制方向、锁屏、屏幕数据与实测往返时间。

屏幕数据在输入循环之外更新，经现有加密连接交换。界面草稿与实时状态分开；双端保存先按配置版本和活跃输出准备并校验，再原子替换各自文件，保留注释和首次界面修改前的备份。两端确认保存后才报告成功。提交期间断网可能使结果无法确认，界面要求重连后核对实际状态。

配对文件先冻结和规范化为公开证书，导入绑定用户已核对的完整指纹。语言切换保留草稿，不修改后端设置。GTK 操作仅在主线程进行，命令与 socket 请求由工作线程处理。
